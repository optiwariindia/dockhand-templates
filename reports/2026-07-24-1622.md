# Dockhand Templates Schema Fix & Compatibility Report

**Date & Time:** 2026-07-24 16:22 IST  
**Lead Engineer:** Om Prakash Tiwari  
**Project:** Dockhand Template Repository  

---

## 📌 Root Cause Diagnosis & Resolution
**Issue:** Dockhand failed to display templates when loading `index.json`.

**Root Causes Identified:**
1. **Incorrect Template Type:** Templates were using `"type": 1` (single container) instead of `"type": 3` (Compose Stack template with Git repository & `stackfile`).
2. **Missing `categories` Array:** Schema expected `categories: ["Infrastructure"]` array format instead of scalar string `category`.
3. **Invalid Inner `version` Keys:** Individual template objects contained an unexpected `"version": "2"` key inside item elements, which caused schema validation errors in Dockhand.
4. **Missing UI Icon Fallback (`logo`):** Portainer v2 / Dockhand schema checks for both `logo` and `icon`.

---

## 🛠️ Actions Taken

1. Updated all 69 `template.json` files:
   - Changed `type` to integer `3` (Compose Stack Template).
   - Added `categories` array property alongside `category` string.
   - Added `logo` property matching `icon` raw SVG URL.
   - Added `platform: "linux"` and `restart_policy: "unless-stopped"`.
   - Removed redundant `"version": "2"` property inside individual template items.
2. Created `templates.json` alongside `index.json` for maximum compatibility with both Portainer and Dockhand UI catalog loaders.
3. Committed and pushed all fixes to GitHub repository `optiwariindia/dockhand-templates` on `main` branch.
